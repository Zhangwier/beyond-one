# 技术规格对照

三份交付物在**同一份提示词**下产出。本文件只记录可验证的技术事实，不做审美评价。

数据来源：对三条成片执行 `ffprobe`，以及对各工程源码的静态阅读。

---

## 交付形态

| | Gemini 4 Argon | Opus 5.5 | DeepSeek 4.1 Flash |
|---|---|---|---|
| 形态 | 单一 HTML 文件 | 多文件 TypeScript 工程 | 多文件 TypeScript 工程 |
| 文件数 | 1 | 27 | 41 |
| 依赖 | 无（浏览器原生 API） | `@napi-rs/canvas` / `opentype.js` / `tsx` / `esbuild` | `playwright-core` |
| 预览方式 | 直接打开文件 | 浏览器 + Vite 风格本地服务 | 自带静态服务 + 即时 TS 转译 |
| 导出方式 | 页面内 MediaRecorder 录制 | Node + Skia 离屏渲染 → ffmpeg | Playwright 驱动无头浏览器 → PNG 帧 → ffmpeg |

## 成片规格

| | Gemini | Opus | DeepSeek |
|---|---|---|---|
| 时长 | 84.0 s | 88.0 s | 84.0 s |
| 分辨率 | 1920×1080 | 1920×1080 | 1920×1080 |
| 帧率 | 60 fps | 60 fps | 60 fps |
| 视频编码 | H.264 | H.264 | H.264 |
| 音频采样率 | 44.1 kHz | **96 kHz** | 48 kHz |
| 声道 | 2 (stereo) | 2 (stereo) | 2 (stereo) |
| 4K 支持 | 页面内切换，重设 canvas 尺寸 | `--scale 2` 全部渲染目标按物理像素重建 | `--scale 2` 同上 |

> 音频采样率三家中 Opus 为 96 kHz，属不常见的导出规格。拼接或对比时需重采样，
> 否则会出现音色差异或播放器兼容问题。

## 时间基准

这是三家分歧最大的设计决策。

| | Gemini | Opus | DeepSeek |
|---|---|---|---|
| 音乐速度 | 120 BPM，一拍 0.5 s | 100 BPM，一拍 0.6 s，一小节 2.4 s | 60 BPM，84 秒 = 84 拍，一小节 4 s |
| 时间来源 | 常量 + 章节表 | `score.ts` 的 `BPM` / `BAR` / `CUE` 表 | `audio/features.json` 帧级包络 + 事件表 |
| 画面如何取时间 | 直接接收 `t` | 场景调用 `bar()` / `beat()` / `at(cue)` | 读取事件表的精确时间戳 |
| 音画同步机制 | 同一条时间轴驱动渲染与合成 | 合成器与场景**读同一份乐谱文件** | 渲染器**不分析波形**，直接读合成器已知的事件时间 |
| 帧函数纯度 | `render(t)` 纯函数 | `renderFrame(ctx, scenes, t)` 纯函数 | `render(t)` 纯函数 |

三家都做到了「渲染器不分析音频波形」。其中 Opus 的做法最彻底：乐谱文件本身就是时间轴的唯一来源，
画面不可能与音乐漂移。

## 渲染技术

| | Gemini | Opus | DeepSeek |
|---|---|---|---|
| 图形层 | Canvas2D | Canvas2D（Skia 后端） | **手写 WebGL2** |
| 渲染目标 | 单个 canvas | 单个 canvas + scratch | 3 个 FBO（纸 / 墨 / 排版）+ 1 个合成 pass |
| 合成方式 | 直接绘制 | 直接绘制 + 后处理（grain / vignette / flash / fade） | **正片叠底**（multiply），字母中可见纸纹 |
| 笔触实现 | 路径描边 | `ribbon()` 沿贝塞尔按宽度轮廓写入 | 折线 → 弧长重采样 → 沿法线挤成带 → 片元着色器算笔芯/枯笔/湿边 |
| 动态模糊 | 无 | `samples(t)` 声明子帧数，渲染器做累积平均 | 无 |
| 随机数 | `Math.sin` 哈希 | `mulberry32` / `hash` / `noise1`（全部播撒种子） | 确定性哈希 |

## 章节结构

三家都响应了提示词的六段式要求，但边界不一致：

| 段落 | Gemini | Opus | DeepSeek |
|---|---|---|---|
| 序章 · 有限 | 0–13 | 0–10.1 | 0–12 |
| 第一章 · 复杂 | 13–26 | 10.1–24.5 | 12–22 |
| 第二章 · 连接 | 26–40 | 24.5–38.9 | 22–40 |
| 第三章 · 突破 | 40–58 | 38.9–58.1 | 40–54 |
| 第四章 · 判断 | 58–70 | 58.1–70.1 | 54–64 |
| 终章 · 可能性 | 70–84 | 70.1–88 | 64–84 |

> 序章结束点分别是 13 / 10.1 / 12 秒，相差约 3 秒。若要做逐段对比，必须按**叙事节点**对齐，
> 按绝对时间对齐会让三条时间轴各自漂移。

## 已知差异与瑕疵

| 项 | 说明 |
|---|---|
| Gemini 排版压字 | 约 30 s、44 s 处顶部标题与节点标签重叠，未修补 |
| Opus 时长 | 88 s，比另两家多 4 秒，属其自身设计 |
| Opus 音频 | 96 kHz，重采样后高频响应会比另两条略亮 |
| Gemini 视觉风格 | 暗底 + 霓虹 + HUD 遥测，是较易被识别为「AI 生成」的一种视觉套路 |

以上均按原样保留，未做任何修改——它们本身就是交付物的一部分。
